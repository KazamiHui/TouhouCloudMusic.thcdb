# 设计哲学
**总则**：
1. 个体行为的基础是个体收集到的信息。
2. 个体可能有意的或无意的进行危险行为。
3. 收录的信息不一定正确。

**信息管理**：
1. 信息的表达形式在部分地区可能不合法。
2. 信息的更改需要管理。
3. 信息和对其的变更次数不小，且每次变更量不会巨大。

**社区管理**：
1. 任一管理个体本身也是使用者。
2. 管理个体不仅在组织内部存在社会关系。
3. 管理的对象是无组织的。

**项目设计**：
1. DDD（领域驱动发展）作为指导。
2. 垂直切片作为服务（在本项目为API）的基本划分。
3. 整洁架构作为业务流程的安排方法。

# FAQ
Q0：为什么resource和社区的设计哲学不同？  
A0：社区更多关注社会关系，resource更多关注更改质量，前者更接近社会学的研究内容，后者更接近工程管理学的研究内容。

Q1：为什么leader持有终止权，leader、resource_manager、superintendent持有恢复权？  
A1：防止leader恶意终止使得组织被迫重建，重建比终止对组织伤害更大。

Q2：为什么leader持有卸下gain_auth的权力，leader、resource_manager、superintendent持有赋予gain_auth的权力？  
A2：人类作为社会动物永远无法剥离其自身的社会属性，其个人社会关系的好坏会驱使个体做出可能不利于组织发展的行为。

Q3：为什么resource的更改记录创建提案者和审核者？  
A3：因为提案通过后对resource产生了实际的影响且由创建提案者产生，提案者需要对其负责；因为resource更改的合法性由审核员决定，所以审核员也需要对其负责。

Q4：如果管理层全部腐化怎么办？  
A4：这个组织死亡，或者有人起义使得管理层换血。

Q5：admin腐化怎么办？  
A5：这是现行组织理论的死穴，只能依赖外部监督（通过舆论等）。

Q6：为什么提案的通过有审核者著名，驳回没有？  
A6：这里需要分几点来作答。
1. 通过对resource造成了实际影响，而驳回则没有；
2. 少量的驳回在以组织整体的视角下实际上更接近审核失误，这是因为人类个体不可能保证完全正确；
3. 大量的驳回会产生外部社群的舆论，出现这种情况只可能是组织腐败或有人恶意攻击。

Q7：为什么文化作品创作者和社团、公司没有标签？  
A7：这里涉及到一个前提假设————事物是静止不变的。而事实上产品确实符合这个假设，每次发布的内容都是静止不变的；但是问题里的这些显然不符合这个假设，社会个体是一个运动且在矛盾中发展的事物，无法拥有一个稳定的分析结果。而标签是完成对事物的分析之后才产生的，而每次完成分析都是在静态的条件下进行的，这就导致标签失去了原有的分类意义。
