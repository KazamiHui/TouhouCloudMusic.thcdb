# 设计哲学
**resource管理**：
1. 社区和谐是resource真实的副产品.
2. 没有账户不可被审计.
3. 人不可信且信息不对称.

**社区管理**：
1. 与上文第一条相同，但是此处生效机制不同.
2. 管理员一定是社区一部分.
3. 管理员来自于社区.
4. 社区事实上钳制管理员.

# FAQ
Q0：为什么resource和社区的设计哲学不同？
A0：因为两者对象不同，所面对的情况不同，方法也不同；社区更多应用了社科下的社会学，而resource更多应用了其下组织（及其管理）的部分.

Q1：为什么leader持有终止权，leader、resource_manager、superintendent持有恢复权？
A1：防止leader恶意终止后无法恢复。

Q2：为什么leader持有卸下gain_permission，leader、resource_manager、superintendent持有赋予gain_permission？
A2：基于对账户必须不因为个人问题而无法参与治理的这一考量做出的设计。

Q3：为什么revision_node记录提案者和审核者？
A3：因为提案通过后对resource产生了实际的影响，所以审核者需要负责，而且提案由提案者产生，所以提案者也需要对其负责；resource_manager对审核者施加压力，需要考虑外部社群，对现任resource_manager及其整个group都会产生压力，他很快的会被撤换。

Q4：如果管理层全部腐化怎么办？
A4：这概率比宇宙现在就坍缩还低，系统不考虑。

Q5：admin腐化怎么办？
A5：抱歉，这一部分几乎是任何社会系统的死穴，只能依赖外部监督（通过舆论等）。

Q6：为什么提案的通过有审核者著名，驳回没有？
A6：这里需要分几点来作答，其一是通过对resource造成了实际影响，而驳回则没有；其二是少量的驳回在以group为整体的视角下实际上更接近审核失误，这是因为收集的数据有限导致的；其三是大量的驳回会产生外部社群的舆论，这些舆论实际上很好的使各个group的管理层自动的去清理自身，因为如果出现这种情况，那么一定是大面积腐败了，就不是系统能够解决的范围而是需要社会来进行。

Q7：为什么文化作品创作者和社团、公司没有tag？
A7：tag更多作为静态标签存在，而这两者作为社会实体（而不是某种物体）存在，社会实体是活动的，这里的哲学是人不可以简单的看作某种物体而是各类系统的综合作用的结果，而社会实体的情况是随历史累加的，如果打上tag必然导致存在各种各样的明显误差。
