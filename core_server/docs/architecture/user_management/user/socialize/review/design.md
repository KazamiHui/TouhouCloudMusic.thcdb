# review系统

可配合[user_comment](../comment/design.md)系统提升审核协作能力.
**举报的数据结构**：
- UID.
类型为整数，默认延续最后一条的UID序列，如果没有则从1开始.
- 提交者.
发起请求的主体，类型为整数，记录发起请求的user的UID.
- 举报描述.
类型为字符串.
- 举报对象的类型.
此处有且仅有comment.
- 举报对象.
- 已处理.
为真值，为真则已处理，否则为未处理.

举报被处理后留存30天.

## 惩戒
社交能力的权限此处只包含`user权限`中的`comment`.
惩罚只涉及账户的主权限.
惩罚的结构为权限（组）和时长.
### 封禁
卸下一个账户除社交能力之外的权限一定时间.
### 中止
卸下一个账户的社交能力的权限一定时间.

## 获取请求内容
给定一个`举报的UID`获取对应的未处理的举报的除UID外的内容.

## 处罚
提供一个`举报的UID`、`审核员的UID`和一种惩戒，如果是评论则可以给出删除.

## 驳回
提供一个`举报的UID`和`理由`.

## 上诉
提供一个`举报的UID`、`权限通知UID`、`理由`对其处罚进行上诉，上诉同样也是一种举报，会复制`举报的UID`对应的举报的举报对象作为上诉对象.
