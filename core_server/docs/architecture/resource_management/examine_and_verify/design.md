# examine and verify模块

对resource的修改请求（组）进行审核.
可配合[user_comment](../../user/socialize/comment/design.md)系统提升审核协作能力.
**提案的数据结构**：
- UID.
类型为整数，默认延续最后一条的UID序列，如果没有则从1开始.
- 提交者.
发起请求的主体，类型为整数，记录发起请求的user的UID.
- 请求的描述.
类型为字符串.
- 请求.
内容为一个或多个请求.

其中，`请求`为一串键值对，如下：
- 执行顺序.
键名为`execution_order`，键值类型为整数.
- 请求类型.
键名为`type`，键值为`create`、`delete`、`modify`、`merge`、`revoke`中的一个.
- 操作.
键名为`operate`，键值为请求的操作.

请求按`执行顺序`的值升序执行，默认第一个执行的对象是后续对象的根节点.

---
**职能**：
- [获取请求内容](#获取请求内容)
- [通过](#通过)
- [驳回](#驳回)

该模块依赖于版本控制系统.

---

## 获取请求内容
给定一个`提案的UID`获取对应的提案的请求描述和请求.

## 通过
提供一个`提案的UID`和`审核员的UID`，对`请求`中按顺序执行`操作`，所有操作成功后按操作顺序形成多个revision_node（见[版本控制系统](../../resource/version_control/design.md)）.

## 驳回
提供一个`提案的UID`和`理由`.
