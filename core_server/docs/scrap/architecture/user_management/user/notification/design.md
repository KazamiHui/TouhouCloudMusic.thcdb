# 通知系统

对用户推送通知，通知主要分为以下几种：
- 系统通知，由系统生成.
- 社交通知，如账户的评论被评论.
- 权限通知，权限被授予、卸下、封禁.

其中，系统通知下分出：
- group通知，由[user管理系统](../../design.md)产生，内容只有group的状态，即group创建、终止、恢复和彻底终止（即group被销毁）会产生通知，发向在group下的所有账户.
- 关注通知，由[账户关注系统](../information/attention/design.md)产生.
- 账户通知，由[user系统](../design.md)产生，只有账户创建和注销时产生，不发向任何人.

系统通知、社交通知、权限通知为三张独立的表.所有通知表头均有UID和时间戳.

系统通知的结构为：
- 接收的group.
账户通知此处为空.
- 接收的账户.
为空则默认该条通知发送给`发送的group`下的所有账户.
账户通知此处为账户的创建和注销的UID.
- 内容.

社交通知的结构为：
- 发送的账户.
- 接收的账户.
- 被评论的评论.
- 内容.

权限通知的结构为：
- 发送的账户.
- 接收的账户.
- 权限.
- 变化状态.
为以下三种之一：
    - 获得.
    - 失去.
    - 封禁或中止.
    该项同时记录时长.

## 获取通知
接收`通知UID`和`通知类型`获取一条通知的内容.  
获取的通知内容不包含通知的UID.

## 查询通知
接收三个参数：
- 账户UID.
为通知的`接收的账户`.
- 时间戳.
为查询的最早的通知.
- 通知类型.
该项为可选，不提供则返回三种通知的UID及其对应的类型.

## 创建通知
接收`通知类型`和`内容`创建一条通知.  
`内容`的规范请需要与`通知类型`对应的类型的通知结构对应.
